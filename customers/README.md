# customers.xlsx — deliberately messy customer list

530 rows, 7 columns, sheet name `Customers`. Generated by python script.

## Schema

| Column | Type in file | Notes |
|---|---|---|
| `customer_id` | text | `CUST-0001` … `CUST-0500`, joins to `orders.csv` |
| `full_name` | text | single column; splitting names is `survey_raw.xlsx`'s job |
| `email` | text | |
| `country` | text | six real countries |
| `signup_date` | **text** | not a date type — three different formats |
| `plan` | text | Free / Basic / Pro / Enterprise |
| `monthly_spend` | **text** | not numeric — contains `-` for missing |

`signup_date` and `monthly_spend` are text on purpose. A column with one bad
cell in it arrives from Excel as text, and discovering that is part of the
lesson.

## The four defects, and why they don't touch

Five tutorials share this file. Each defect is confined to its own block of
rows, so **no row carries two problems**:

| Block | Rows | Defect | Count |
|---|---|---|---|
| A | `CUST-0001`–`0030` | duplicated later in the file, exact copies | 30 extra rows |
| B | `CUST-0100`–`0159` | missing values as `N/A`, blank, and `-` | 60 cells |
| C | `CUST-0200`–`0299` | `signup_date` as `DD/MM/YYYY` or `March 14, 2024` | 100 rows |
| D | `CUST-0300`–`0399` | `country` as `PL` / `poland` / `POLAND` / `Polska` etc. | 100 rows |

Everything else is clean.

This matters because the four narrow tutorials each fix one defect and each
quote a row count. If a duplicated row also had a null, the count would depend
on which tutorial the reader did first. Verified: **cleaning in any order gives
byte-identical output.**

The blocks also don't share a column. Missing values live in `full_name`,
`email`, and `monthly_spend`; country variants live in `country`. So the
standardize tutorial never meets a blank, and the missing-data tutorial never
meets a spelling variant.

## Numbers to quote

**Before cleaning**

- 530 rows, 7 columns
- 30 exact duplicate rows
- missing: `email` 21, `full_name` 21, `monthly_spend` 18
- `signup_date`: 430 ISO, 100 non-ISO
- `country`: 21 distinct strings for 6 real countries

**After cleaning**

- 500 rows
- `country`: 6 distinct values
- `signup_date`: proper datetime
- nulls remain: `full_name` 21, `email` 21, `monthly_spend` 18 — the missing
  tokens become real nulls; they are not invented values

## Deliberately excluded

**Near-duplicates.** Same `customer_id`, differing cells. Realistic, but the
row count after deduplication would depend on whether the reader matched on all
columns or just the id, and two tutorials would disagree.

**Ambiguous dates.** Every day-of-month in this file is 13 or higher, so
`14/03/2024` cannot be misread as a month. Real exports do contain `03/04/2024`
and it is genuinely dangerous — worth a sentence in the date tutorial — but a
trap that silently produces wrong dates is bad in a fixture whose numbers are
quoted on five pages.
